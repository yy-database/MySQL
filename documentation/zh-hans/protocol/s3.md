# S3 兼容协议详解

**we-trust-s3** 实现了 Amazon S3 兼容的对象存储接口，使 YYKV 能够作为海量非结构化数据的存储后端。

## 1. 架构实现

不同于传统文件系统，YYKV 将 S3 协议层直接构建在 **HAL (硬件抽象层)** 之上：
- **RESTful 接口**: 通过 HTTP/HTTPS 提供标准的 S3 API。
- **虚拟桶 (Virtual Buckets)**: 将 S3 的 `Bucket` 概念映射为 YYKV 的租户级逻辑命名空间。
- **对象映射**: `Key` 映射为存储引擎的键，`Body` 利用 `yykv-io` 的 Direct I/O 进行大块连续写入。

## 2. 支持的 API

- **Service 操作**: `ListBuckets`
- **Bucket 操作**: `GetBucket (List Objects)`, `HeadBucket`
- **Object 操作**:
  - `PutObject`: 支持分块上传 (Multipart Upload) 优化。
  - `GetObject`: 支持 Range 请求，实现物理级别的偏移量读取。
  - `DeleteObject`: 原子化删除。
  - `HeadObject`: 获取元数据。

## 3. 存储优化：大对象切片

针对 S3 场景，YYKV 采用了特殊的存储策略：
- **自动分片**: 大于 4MB 的对象会被自动切分为多个物理 Page。
- **混合存储**: 对象的元数据存储在高性能 SSD (Blaze 层)，而对象主体数据根据访问频率自动在 SSD 与大容量 HDD 之间迁移。

## 4. 安全认证

兼容标准的 S3 V4 签名算法 (`AWS4-HMAC-SHA256`)：
- 客户端使用 `AccessKey` 和 `SecretKey` 对请求进行签名。
- YYKV 内部鉴权模块验证签名，并将其关联至对应的 `TenantID`。

## 5. 使用场景

- **云原生备份**: 使用 `aws-cli` 或 `rclone` 直接将备份数据同步到 YYKV。
- **多模态应用**: 同一个租户可以在 `we-trust-postgres` 下操作结构化元数据，同时在 `we-trust-s3` 下存储关联的大型媒体文件。
