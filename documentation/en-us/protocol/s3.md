# S3 Compatibility Protocol

**we-trust-s3** implements an Amazon S3-compatible object storage interface, allowing YYKV to serve as a backend for massive unstructured data.

## 1. Architectural Implementation

Unlike traditional file systems, the YYKV S3 protocol layer is built directly on the **HAL (Hardware Abstraction Layer)**:
- **RESTful Interface**: Provides standard S3 APIs via HTTP/HTTPS.
- **Virtual Buckets**: Maps S3 `Bucket` concepts to tenant-level logical namespaces in YYKV.
- **Object Mapping**: `Key` maps to storage engine keys; `Body` uses `yykv-io` Direct I/O for large contiguous writes.

## 2. Supported APIs

- **Service Operations**: `ListBuckets`
- **Bucket Operations**: `GetBucket (List Objects)`, `HeadBucket`
- **Object Operations**:
  - `PutObject`: Supports Multipart Upload optimizations.
  - `GetObject`: Supports Range requests for physical-level offset reading.
  - `DeleteObject`: Atomic deletions.
  - `HeadObject`: Metadata retrieval.

## 3. Storage Optimization: Object Slicing

For S3 scenarios, YYKV employs specific storage strategies:
- **Automatic Sharding**: Objects larger than 4MB are automatically sliced into multiple physical pages.
- **Hybrid Storage**: Object metadata is stored in high-performance SSDs (Blaze tier), while body data automatically migrates between SSD and high-capacity HDD based on access frequency.

## 4. Security and Authentication

Compatible with standard S3 V4 signing (`AWS4-HMAC-SHA256`):
- Clients sign requests using `AccessKey` and `SecretKey`.
- The internal YYKV authentication module verifies the signature and associates it with the corresponding `TenantID`.

## 5. Usage Scenarios

- **Cloud-Native Backup**: Use `aws-cli` or `rclone` to sync backup data directly to YYKV.
- **Multi-Modal Applications**: A single tenant can operate on structured metadata via `we-trust-postgres` while storing associated large media files via `we-trust-s3`.
