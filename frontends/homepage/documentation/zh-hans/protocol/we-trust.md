# We-Trust 协议详解

**We-Trust** 是 YYKV 的原生高性能二进制通信协议，专为极致低延迟和大规模多租户环境设计。它位于存储引擎的通信层，负责节点间、客户端与服务端之间的高效数据交换。

## 1. 协议设计目标

- **微秒级延迟**: 采用紧凑的二进制布局，最小化编解码开销，支持零拷贝解析。
- **原生多租户**: 在协议头部深度集成租户标识，支持物理层面的流量控制和资源隔离。
- **强安全性**: 每个数据包都包含加密签名，防止中间人攻击和未授权访问。
- **流式处理**: 配合 `tokio-util` 的 `Codec` 框架，支持海量数据的流式扫描与背压控制。

## 2. 报文结构 (80 字节头部)

We-Trust 报文由 **80 字节固定头部** 和 **可选 Payload** 组成。

### 2.1 头部布局

| 偏移量 | 长度 | 字段名 | 说明 |
| :--- | :--- | :--- | :--- |
| 0 | 2 | `Magic` | 协议魔数，固定为 `0x59 0x59` (ASCII "YY") |
| 2 | 1 | `Version` | 协议版本，当前为 `0x01` |
| 3 | 1 | `MsgType` | 消息类型 (1: Put, 2: Get, 4: Query, 12: KQL 等) |
| 4 | 4 | `Flags` | 控制标记（位掩码：0x01-压缩, 0x02-加密, 0x04-高优先级） |
| 8 | 4 | `Length` | 整个报文的字节长度（包含头部和 Payload） |
| 12 | 16 | `RequestID` | 唯一请求 ID (UUID)，用于异步匹配响应 |
| 28 | 16 | `TenantID` | 租户 ID (UUID)，存储引擎据此进行物理资源路由 |
| 44 | 32 | `Signature` | 基于 HMAC-SHA256 的头部及 Payload 签名 |
| 76 | 4 | `Reserved` | 预留字段，用于未来功能扩展 |

### 2.2 消息类型 (`MessageType`)

- **`0x01` Put**: 写入/更新键值对。
- **`0x02` Get**: 获取键值对。
- **`0x04` Query**: 执行复杂的算子图查询 (OpsGraph)。
- **`0x05` Rbq**: 架构白皮书定义的可靠字节队列操作。
- **`0x0C` KQL**: 执行 YYKV 原生查询语言指令。
- **`0x0B` Heartbeat**: 节点间存活检测。
- **`0xFF` Error**: 错误响应。

## 3. 连接与认证流程

1. **建立连接**: 客户端通过 TCP 建立连接（默认端口 `8889`）。
2. **握手认证**: 客户端发送 `MessageType::Auth` 报文，包含 `TenantID` 和加密后的 `SecretKey`。
3. **建立会话**: 服务端验证签名并返回 `Response`。后续所有报文必须携带有效的 `Signature` 以供实时校验。

## 4. 性能优化特性

- **CRC32C 校验**: 针对物理介质优化的循环冗余校验。
- **零拷贝解析**: 头部字段严格对齐，支持直接从缓冲区读取结构体，避免内存拷贝。
- **批处理支持**: 支持在一个连接中流水线 (Pipelining) 发送多个请求。
